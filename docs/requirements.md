### 1.4 术语定义

|术语|我的解释|
|-|-|
|节点 Node|差不多就是各个负责处理信息或者接收信息的枢纽，作为一个节点，总体上围绕节点开始运行这个系统|
|话题 Topic|节点之间传输信息的通道，可以类比为一个贴吧讨论组，一组传一组传递消息|
|消息 Message|就是信息，数据的内容，载体，里面有各种各样的属性，比如什么内容啊，发布时间啥的|
|发布者 Publisher|他其实是一个节点，能够向某个节点通过话题这个通道传输消息“Message”|
|订阅者 Subscriber|也是一个节点，从中间的那个承载枢纽获得信息|
|单例|节点，作用为枢纽，获得信息和被人读取信息，类似于一个告示牌，有人在上面写今天的各种消息，有人从上面了解今天的各种消息|

### 3.3 必做功能

**FR-01 节点抽象基类**

* **描述**：给所有节点定一套统一规范，每个节点都要有名字、能初始化、能关闭。
* **规则**：
  * R1 每个节点有一个全局唯一的名字，名字不能为空，也不能全是空格。
  * R2 名字在创建时确定，之后只读，不能修改。
  * R3 初始化（init）和关闭（shutdown）是纯虚函数，子类必须实现，并且要输出对应日志。
  * R4 基类的析构函数必须是虚函数，避免用基类指针删除子类对象时出问题。
* **验收**：Node 不能直接创建，子类漏实现 init 或 shutdown 时编译不通过。

**FR-02 发布者节点**

* **描述**：继承 Node，负责往指定话题发消息。
* **规则**：
  * R1 持有话题名，只读。
  * R2 初始化时输出初始化日志，并向 ROS 核心注册自己。
  * R3 发布时接收一段字符串（模拟传感器数据），内部封装成 Message。
  * R4 发布时输出日志，日志里带上话题名和消息内容。
  * R5 关闭时输出关闭日志。
  * R6 发布完直接返回，不等待订阅者处理。
* **验收**：初始化后能在 ROS 的发布者表里查到；发布后该话题的订阅者能收到消息。

**FR-03 订阅者节点**

* **描述**：继承 Node，订阅话题并被动接收消息。
* **规则**：
  * R1 持有话题名，只读。
  * R2 初始化时输出初始化日志，并向 ROS 核心注册自己。
  * R3 收到消息时输出接收日志，日志里要包含消息内容和时间戳。
  * R4 关闭时输出关闭日志。
* **验收**：发布者发一条消息，该话题下所有订阅者都输出接收日志。

**FR-04 消息封装**

* **描述**：节点之间传的数据统一装在 Message 里。
* **规则**：
  * R1 封装字符串内容。
  * R2 创建时自动生成时间戳，格式固定为 YYYY-MM-DD HH:MM:SS。
  * R3 内容和时间戳对外只读，不提供任何修改接口。
  * R4 内容为空时直接拒绝，抛出异常。
* **验收**：收到的消息内容和发的一致；时间戳格式正确；外部改不了内容。

**FR-05 通信核心（单例）**

* **描述**：整个程序只有一个 ROS 对象，所有节点都向它注册，消息也由它转发。
* **规则**：
  * R1 全局唯一，禁止拷贝构造和赋值。
  * R2 维护两张表：话题对应哪些发布者、话题对应哪些订阅者。
  * R3 另外维护一个已注册节点名的集合，用来检测重复注册。
  * R4 注册时检查空指针、空话题名、重复节点名。
* **验收**：两次获取实例得到同一个地址；注册后映射表里有记录；重名注册被拒绝。

**FR-06 消息转发**

* **描述**：发布者把消息交给 ROS，ROS 负责发给该话题下的所有订阅者。
* **规则**：
  * R1 按注册顺序依次调用每个订阅者的接收接口。
  * R2 话题下没有任何订阅者，就视为“话题不存在”，抛出 TopicException。
  * R3 某个订阅者处理时抛异常，记录错误日志后继续发给后面的订阅者，不能让整个流程挂掉。
* **验收**：一个话题挂 3 个订阅者，发一次 3 个都收到；话题不存在时抛异常且程序不崩溃。

**FR-07 统一关闭**

* **描述**：一次性关闭所有已注册节点。
* **规则**：
  * R1 遍历所有发布者和订阅者，调用它们的关闭接口。
  * R2 关闭完成后清空映射表和名称集合。
  * R3 重复调用不能崩溃。
* **验收**：调用后每个节点都输出关闭日志；第二次调用没有副作用也不报错。

**FR-08 异步发布**

* **描述**：发布消息时不需要等订阅者处理完才返回。
* **规则**：
  * R1 发布接口把消息交出去后就返回，不返回订阅者的处理结果。
  * R2 本期是单线程实现，转发在调用过程中同步完成，但发布者不关心、也不需要等待订阅者的响应。
* **验收**：发布调用不依赖订阅者的返回值；订阅者处理慢或出错不影响发布者的正常流程。

**FR-09 异常处理**

* **描述**：遇到非法输入或非法操作时程序不能崩溃，要抛出看得懂的异常。
* **规则**：
  * R1 所有异常继承自 RosException，分为 NodeException、TopicException、MessageException 三类。
  * R2 异常信息里要带上是哪个节点或哪个话题出的问题。
  * R3 顶层统一捕获异常，输出错误日志后正常退出，不允许出现崩溃或者 core dump。
* **验收**：第 6 节列出的异常场景逐个测试，全部不崩溃，报错信息能看懂。

**FR-10 日志输出**

* **描述**：把系统运行过程中的关键动作记录下来。
* **规则**：
  * R1 每条日志包含时间戳、级别、节点或话题、说明。
  * R2 初始化、关闭、发布、接收这四类动作必须记录。
  * R3 日志本身出问题不能影响主流程，比如文件打不开时只输出到控制台。
* **验收**：跑一遍演示程序，四类日志都能看到，格式统一。
