### 1.4 术语定义

|术语|我的解释|
|-|-|
|节点 Node|差不多就是各个负责处理信息或者接收信息的枢纽，作为一个节点，总体上围绕节点开始运行这个系统|
|话题 Topic|节点之间传输信息的通道，可以类比为一个贴吧讨论组，一组传一组传递消息|
|消息 Message|就是信息，数据的内容，载体，里面有各种各样的属性，比如什么内容啊，发布时间啥的|
|发布者 Publisher|他其实是一个节点，能够向某个节点通过话题这个通道传输消息“Message”|
|订阅者 Subscriber|也是一个节点，从中间的那个承载枢纽获得信息|
|单例|节点，作用为枢纽，获得信息和被人读取信息，类似于一个告示牌，有人在上面写今天的各种消息，有人从上面了解今天的各种消息|

## 2. 总体描述

### 2.1 产品定位

用来公示信息的一个系统，单进程

### 2.2 用户与使用场景

|角色|关心什么|
|-|-|
|学生，工人|当日的信息，例如天气，温度|

### 2.3 运行环境

|项|要求|
|-|-|
|操作系统|Windows 10/11（主要），Linux 也能编译运行|
|编译器|MSVC 2022 及以上 / GCC 9 及以上 / Clang 10 及以上|
|语言标准|C++17|
|构建工具|CMake 3.16 及以上|
|第三方依赖|无，只用 C++ 标准库|

### 2.4 设计约束

|编号|约束|
|-|-|
|C-01|只使用 C++ 标准库，不引入任何第三方依赖|
|C-02|不使用全局变量保存状态（单例对象除外）|
|C-03|资源统一用智能指针和 RAII 管理，禁止裸 new/delete|
|C-04|公共接口保证 const 正确性|
|C-05|遇到非法输入时程序不得崩溃，必须抛出语义清晰的异常|
|C-06|编译开启警告并保持零警告|

### 2.5 假设与依赖

* 单进程运行，不涉及跨进程通信和网络
* 单线程，不涉及并发和加锁
* 消息在进程内以对象形式传递，不做序列化
* 节点从初始化到统一关闭期间一直存在，不考虑运行中途被销毁

### 3.2 需求条目模板

**FR-xx 功能名称**

* **描述**：一句话说明这个功能
* **规则**：

  * R1 ...
  * R2 ...
* **验收**：怎么验证它做对了

> 提示：规则写「边界和约束」，比如「名称不能为空」「重复注册要拒绝」；
> 验收写「可观察的结果」，比如「日志出现」「表中数量 +1」。

### 3.3 必做功能

**FR-01 节点抽象基类**

* **描述**：给所有节点定一套统一规范，每个节点都要有名字、能初始化、能关闭。
* **规则**：
  * R1 每个节点有一个全局唯一的名字，名字不能为空，也不能全是空格。
  * R2 名字在创建时确定，之后只读，不能修改。
  * R3 初始化（init）和关闭（shutdown）是纯虚函数，子类必须实现，并且要输出对应日志。
  * R4 基类的析构函数必须是虚函数，避免用基类指针删除子类对象时出问题。
* **验收**：Node 不能直接创建，子类漏实现 init 或 shutdown 时编译不通过。

**FR-02 发布者节点**

* **描述**：继承 Node，负责往指定话题发消息。
* **规则**：
  * R1 持有话题名，只读。
  * R2 初始化时输出初始化日志，并向 ROS 核心注册自己。
  * R3 发布时接收一段字符串（模拟传感器数据），内部封装成 Message。
  * R4 发布时输出日志，日志里带上话题名和消息内容。
  * R5 关闭时输出关闭日志。
  * R6 发布完直接返回，不等待订阅者处理。
* **验收**：初始化后能在 ROS 的发布者表里查到；发布后该话题的订阅者能收到消息。

**FR-03 订阅者节点**

* **描述**：继承 Node，订阅话题并被动接收消息。
* **规则**：
  * R1 持有话题名，只读。
  * R2 初始化时输出初始化日志，并向 ROS 核心注册自己。
  * R3 收到消息时输出接收日志，日志里要包含消息内容和时间戳。
  * R4 关闭时输出关闭日志。
* **验收**：发布者发一条消息，该话题下所有订阅者都输出接收日志。

**FR-04 消息封装**

* **描述**：节点之间传的数据统一装在 Message 里。
* **规则**：
  * R1 封装字符串内容。
  * R2 创建时自动生成时间戳，格式固定为 YYYY-MM-DD HH:MM:SS。
  * R3 内容和时间戳对外只读，不提供任何修改接口。
  * R4 内容为空时直接拒绝，抛出异常。
* **验收**：收到的消息内容和发的一致；时间戳格式正确；外部改不了内容。

**FR-05 通信核心（单例）**

* **描述**：整个程序只有一个 ROS 对象，所有节点都向它注册，消息也由它转发。
* **规则**：
  * R1 全局唯一，禁止拷贝构造和赋值。
  * R2 维护两张表：话题对应哪些发布者、话题对应哪些订阅者。
  * R3 另外维护一个已注册节点名的集合，用来检测重复注册。
  * R4 注册时检查空指针、空话题名、重复节点名。
* **验收**：两次获取实例得到同一个地址；注册后映射表里有记录；重名注册被拒绝。

**FR-06 消息转发**

* **描述**：发布者把消息交给 ROS，ROS 负责发给该话题下的所有订阅者。
* **规则**：
  * R1 按注册顺序依次调用每个订阅者的接收接口。
  * R2 话题下没有任何订阅者，就视为“话题不存在”，抛出 TopicException。
  * R3 某个订阅者处理时抛异常，记录错误日志后继续发给后面的订阅者，不能让整个流程挂掉。
* **验收**：一个话题挂 3 个订阅者，发一次 3 个都收到；话题不存在时抛异常且程序不崩溃。

**FR-07 统一关闭**

* **描述**：一次性关闭所有已注册节点。
* **规则**：
  * R1 遍历所有发布者和订阅者，调用它们的关闭接口。
  * R2 关闭完成后清空映射表和名称集合。
  * R3 重复调用不能崩溃。
* **验收**：调用后每个节点都输出关闭日志；第二次调用没有副作用也不报错。

**FR-08 异步发布**

* **描述**：发布消息时不需要等订阅者处理完才返回。
* **规则**：
  * R1 发布接口把消息交出去后就返回，不返回订阅者的处理结果。
  * R2 本期是单线程实现，转发在调用过程中同步完成，但发布者不关心、也不需要等待订阅者的响应。
* **验收**：发布调用不依赖订阅者的返回值；订阅者处理慢或出错不影响发布者的正常流程。

**FR-09 异常处理**

* **描述**：遇到非法输入或非法操作时程序不能崩溃，要抛出看得懂的异常。
* **规则**：
  * R1 所有异常继承自 RosException，分为 NodeException、TopicException、MessageException 三类。
  * R2 异常信息里要带上是哪个节点或哪个话题出的问题。
  * R3 顶层统一捕获异常，输出错误日志后正常退出，不允许出现崩溃或者 core dump。
* **验收**：第 6 节列出的异常场景逐个测试，全部不崩溃，报错信息能看懂。

**FR-10 日志输出**

* **描述**：把系统运行过程中的关键动作记录下来。
* **规则**：
  * R1 每条日志包含时间戳、级别、节点或话题、说明。
  * R2 初始化、关闭、发布、接收这四类动作必须记录。
  * R3 日志本身出问题不能影响主流程，比如文件打不开时只输出到控制台。
* **验收**：跑一遍演示程序，四类日志都能看到，格式统一。

### 3.4 加分功能

**FR-11 自定义消息类型**

* **描述**：在普通消息基础上增加温度和湿度字段。
* **规则**：
  * R1 继承 Message，重写 toString()。
  * R2 通过基类引用传递时不丢失派生字段（不发生对象切片）。
* **验收**：订阅者日志中出现“温度=25.3 湿度=60.0”。

**FR-12 日志分级与持久化**

* **描述**：日志分 INFO / WARN / ERROR 三级，同时输出控制台和文件。
* **规则**：
  * R1 文件路径为 logs/ros_sim.log，追加写入。
  * R2 目录不存在时自动创建，文件打不开时降级为仅控制台。
* **验收**：运行后 logs/ros_sim.log 中有完整记录。

**FR-13 全局异常处理**

* **描述**：main 中分类捕获异常，程序不崩溃。
* **规则**：
  * R1 按异常类型分别处理，输出 ERROR 日志。
  * R2 出错时返回退出码 1。
* **验收**：向无订阅者话题发布，日志输出 ERROR 且进程正常结束。

**未实现的功能**

FR-14 服务/客户端、FR-15 动态增删节点本期未实现。原因是时间有限，且不影响核心通信模型的完整性。

## 5. 用例

### UC-01 初始化节点

* **参与者**：演示程序
* **前置条件**：无
* **主流程**：创建节点 → 调用 init() → 输出初始化日志 → 注册到 ROS 核心
* **异常流程**：名称为空或重复 → 抛 NodeException

### UC-02 发布消息

* **参与者**：发布者
* **前置条件**：发布者已初始化，话题下存在订阅者
* **主流程**：接收字符串数据 → 构造 Message → 输出发布日志 → ROS 转发给全部订阅者
* **异常流程**：话题下无订阅者 → 抛 TopicException

### UC-03 接收消息

* **参与者**：订阅者
* **前置条件**：订阅者已初始化
* **主流程**：收到消息 → 输出接收日志（内容 + 时间戳）

### UC-04 统一关闭

* **参与者**：演示程序
* **前置条件**：存在已注册节点
* **主流程**：调用 shutdownAll() → 遍历节点调用 shutdown() → 输出关闭日志 → 清空注册表

### UC-05 异常处理

* **参与者**：main
* **前置条件**：任意模块抛出异常
* **主流程**：捕获异常 → 输出 ERROR 日志 → 返回退出码 1

## 6. 异常场景清单

|编号|场景|触发条件|期望行为|异常类型|
|-|-|-|-|-|
|E-01|空节点名|名称为空或全为空白|拒绝创建，程序不崩溃|NodeException|
|E-02|空话题名|话题为空或全为空白|拒绝创建，程序不崩溃|TopicException|
|E-03|空消息|消息内容为空|拒绝发布|MessageException|
|E-04|节点重名|已存在同名节点再次注册|拒绝注册，原有节点不受影响|NodeException|
|E-05|重复初始化|同一节点 init 两次|抛出异常|NodeException|
|E-06|话题不存在|转发的 topic 下没有订阅者|抛出异常，程序不崩溃|TopicException|
|E-07|未初始化就发布|节点未 init 就 publish|抛出异常|NodeException|
|E-08|空指针注册|注册空指针节点|抛出异常|NodeException|

## 7. 数据与日志

### 7.1 消息数据

|字段|类型|约束|
|-|-|-|
|content|string|不能为空|
|timestamp|string|创建时自动生成，格式 YYYY-MM-DD HH:MM:SS|

### 7.2 日志格式

每条日志由「时间、级别、上下文、描述」四部分组成：

```
[时间] [级别] [上下文] 描述
```

示例：

```
[2026-11-17 20:30:00] [INFO] [Node:pub_temp] 发布消息 topic=/room/temp 内容=25.3
[2026-11-17 20:30:00] [ERROR] [Topic] 话题不存在或没有订阅者: /room/none
```
